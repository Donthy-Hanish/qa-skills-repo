## What This Project Is

PECO Load Tester is a **HAR-to-k6 compiler** for load-testing PECO's AI-search platform. It is a Node.js tooling project with no npm dependencies, test suite, or build step. The workflow is:

1. Capture browser traffic as a HAR file using Playwright
2. Run the compiler (Node.js CLI) to emit a k6 script, a post-processor, and a PowerShell runner
3. Execute the generated runner to run the test and produce an HTML report

## Prerequisites

- Node.js 18+
- k6 (from https://k6.io)
- Playwright Chromium: `npx playwright install chromium`
- PowerShell 5.1+

## Workflow Commands

```powershell
# 1. Capture HAR from live UI (interact with browser, then close)
npx playwright open https://<peco-url>/ --save-har=peco_search.har

# 2. Select a query pool (copy one of the 4 pools into queries.json)
Copy-Item queries-full-geocoded.json queries.json -Force

# 3. Compile HAR → k6 script (interactive prompts for VUs, duration, sleep)
node peco_smart_compiler_v1.js

# 4. Run the load test (wrapper auto-generated by step 3)
.\run-search.ps1

# 5. View results
#    HTML report: reports/search/*_report.html (latest timestamped file)
#    Failure JSON: reports/search/*_failures.json
```

## Query Pools

| File | Queries | When to use |
|------|---------|-------------|
| `queries-smoke.json` | 5 | Fast smoke / CI validation |
| `queries-full.json` | 100 | Realistic load, no geolocation |
| `queries-full-geocoded.json` | 100 | Realistic load with real city coordinates |
| `queries-edge-cases.json` | 10 | SCIF/HUBZone/regulatory/complex corner cases |

Place the chosen file at `queries.json` in the project root before compiling.

## Architecture

### What the Compiler Does

`peco_smart_compiler_v1.js` reads a HAR file and auto-detects:
- **API host** — most-frequent origin in the HAR
- **API path prefix** — e.g., `/api/v1`
- **Auth header** — `X-API-Key`, `Api-Key`, `Authorization`, etc.
- **AI/LLM endpoints** — URLs containing `llm`, `vector`, `chat`, `embed`, `rag`, `search`

It then emits three files:
- `performance/peco_<flow>_smart_load.js` — the k6 test script
- `peco_postprocess.js` — post-test log parser that injects a Failure Diagnostics section into the HTML report
- `run-<flow>.ps1` — PowerShell wrapper: runs k6, tees stdout to a timestamped log, calls the post-processor

### Generated k6 Script Behavior

- Loads `queries.json` at startup via k6 `SharedArray`
- Each VU picks a different query per iteration using a deterministic formula `((__VU-1)*7919 + __ITER) % length` to defeat LLM response caching
- Logs failures to stdout between `__PECO_FAILURE_BEGIN__` / `__PECO_FAILURE_END__` markers
- Thresholds: AI endpoints p(95) < 10 s, non-AI p(95) < 2 s, HTTP error rate < 5%

### Failure Diagnostics (Post-Processing)

`peco_postprocess.js` (auto-generated at compile time) parses the k6 log file, extracts `__PECO_FAILURE_*` markers, groups failures by endpoint + status code, and inserts a rich HTML section (with full request/response headers and bodies) into the base k6 HTML report.

### Output Directories (auto-created at runtime)

- `hars/` — HAR files organized by flow
- `performance/` — generated k6 scripts
- `logs/` — timestamped k6 stdout logs
- `reports/<flow>/` — HTML reports and `failures.json`

## Cost Control

The compiler estimates total LLM call count and dollar cost (≈ $0.001–$0.01 per call) upfront and prompts the user to confirm before generating the script. Adjust VUs, duration, and sleep-between-iterations to control spend.
